# Описание сделанного
Данная работа направлена на изучение работы прерываний. Если во время работы программы случается исключение или прерывание (их общее название – ловушка = trap), то процессор бросает исполнение текущей программы и уходит в обработчик. В нашем случае вызывается sbreak. Тогда
1) в CSR записывается информация по ловушке
    - в mepc при исключении кладется адрес инструкции, которая его вызвала, при прерыании – адрес инструкции, которая должна была выполниться следующей
    - в mcause записывается код причины ловушки
    - и др
2) PC <- mepc
3) Обработчик запустился

Обработчик  - это программа. И написав ее, разработчик должен указать, где ее искать, поместив адрес начала обработчика в вектор прерываний для соответствующего прерывания. В нашем случае - один обработчик на все прерывания - trap_vector. Адрес начала обработчика помещается в CSR mtvec.

Код trap_vector был изменен так, чтобы он выводил в консоль строку BP. Мы циклом проходимся по всем символам строки и помещаем их по очереди в адрес, который исопользуется для вывода (0xf0000000).

Но возникает проблема, процессор всегда после сброса начинает с 0x200. Это прописано в SCR1_ARCH_RST_VECTOR. И до изменений все смещения подобраны были так, чтобы _start начинался с этого адреса, но мы добавили инструкции и адреса сместились. Поэтому пришлось определить точный адрес _start через .text.start. А также изменили адрес trap_vector с помощью .org 0x740, 0x00 (выбрано не 0x840, а 0x740, потому что org указывает смещение относительно начала секции, а не абсолютный адрес,  а начало секции - 0x100).

В результате работы мы увидели как обрабатывается sbreak и настроили обработчик. Тест проходит
